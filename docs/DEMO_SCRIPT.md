# Five-minute demo script

**Setup (before the call):** run `npm run demo:reset`, then `npm start`. Open http://localhost:8787 at 125% browser zoom for Teams. Set "Acting as" to *R. Alvarez (reviewer)*. Keep a terminal ready with `npm run demo:walkthrough` as the fallback.

**Hosted alternative:** the browser-only build at https://claude.ai/artifact/KgfLNw5us6t1U3ga1uixrA (add `#reviewed` to start at step 4, or `#changed` to open on 3 Change impact right after the requirement change) needs no local setup. It supports the same path, but state resets on reload. Add `,guide` (for example `#reviewed,guide`) to show an opt-in presenter strip: seven steps that tick off from the app's real state, a **Go** button that opens the right tab and outlines the next button, and *Reset to:* buttons (click twice) that reload into a stage. The guide never judges, decides or imports anything itself. Share it from the page's Share menu before sending it to anyone.

**Fallback levels:** (1) `npm run demo:reset -- --stage=reviewed` jumps straight to step 4; `npm run demo:reset -- --stage=changed` (or `#changed` in the hosted build) jumps past the requirement change, with v3 already `STALE`. Stage setup is recorded as scripted demo setup: History shows a `SCRIPTED SETUP` chip on those events, and the setup acceptance rationale starts with "Scripted demo setup:". (2) `npm run demo:walkthrough` prints the whole path from real execution in the terminal; say it is the CLI, not the UI. (3) The screenshots in `docs/screenshots/` are static captures from an earlier run and should be labeled that way.
