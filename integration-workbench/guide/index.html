Integration Workbench

A local application that follows one engineering model through a series of changes. It keeps each element's identity, generates and tests an API contract for a consuming app, and blocks releases that would break that app. It also proposes links between maintenance records and model elements, which a person must approve.

Scope. All data is synthetic. This is not a Cameo, Teamwork Cloud or SysML integration, and it says nothing about KBR's own systems. It explores one integration pattern that was described in conversation. Logins are fixed demo tokens, not real authentication. No real AI model has been run: the "model" in the demo replays scripted outputs.

What was built

Eight working parts

Model importer

Reads a model export, keeps a stable identity per element across renames, tracks revisions by their declared parent, and quarantines conflicts, out-of-order and malformed imports instead of applying them.

lucidwb/importer.py

Contract generator

Builds an OpenAPI 3.1.1 contract from a reviewed "projection" that allowlists which fields a consumer sees. Flags removed fields, unit changes and reversed relationships before release.

lucidwb/projection.py

Release manager

Builds a candidate, validates its real HTTP responses against the contract, asks the consumer to run its own checks, then switches the live release in one step. Rollback is supported.

lucidwb/release.py

Mock consumer app

A separate "equipment dashboard" with its own code, database and expectations. It reads the API over HTTP and ignores duplicate or out-of-date events.

consumer_app/

Link review

Proposes record-to-element links with exact quotes that must match the stored source text. Accepting one requires the approver role and the proposal's current version, and fails if the model changed since.

lucidwb/links.py

Safe retries and delivery

Retried requests return the original result instead of repeating the change. Events to the consumer are saved with the change and resent until acknowledged.

receipts.py · outbox.py

Web UI

Panels for model revisions, releases and contract changes, link review with highlighted evidence, and a full operation history. Demo buttons import each test scenario.

web/

Container and access gate

One Docker container for Railway (or Fly.io, Render, any Docker host). A shared access code protects every page, and the server runs as a non-root user.

How to use it · 1

Run it on your computer

You need Python 3.10 or newer and a terminal. From the repository root:

cd workbench
./scripts/setup.sh                        # one-time: installs pinned packages into .venv
.venv/bin/python scripts/run.py --reset   # starts the workbench and the consumer with fresh data

Leave that running. In a second terminal, load the starting data:

cd workbench && .venv/bin/python scripts/seed.py

Workbench

http://127.0.0.1:8780/
Main UI. Pick a demo identity in the header.

Consumer dashboard

http://127.0.0.1:8781/
What the consuming app currently sees. Also served at /consumer/.

These links work only on the computer running the workbench. To start over, stop run.py and run it again with --reset.

How to use it · 3

The five-minute walkthrough

Before you start, tick send Idempotency-Key in Demo controls, so the retry in step 6 works. For a hands-free version, run .venv/bin/python scripts/demo.py --pause and press Enter between steps.

  1. Import the first model and publish it carol

    Click Import A, then Build candidate (projection 1.0.0), Run consumer checks, and Activate.

    You should see: import accepted_head with 12 elements, the candidate tested_pass, and the consumer dashboard showing revision 7c1e9a.

  2. Send the same model again carol

    Click Import A a second time.

    You should see: duplicate_no_change pointing at the first import, with identical counts and no new events.

  3. Review proposed links carol → alice

    Run the deterministic proposals, then the fixture-model proposals. Note the FIXTURE MODE label, the struck-through made-up quote, and the forged note that gains no authority. Switch to alice. For record MR-1003, reject the DE sensor and accept the NDE sensor; note N-2 explains why.

    You should see: two competing candidates for MR-1003, then one link with status reviewer_accepted.

  4. Change the model carol → alice → carol

    As carol, import B, which renames the gateway. As alice, try to accept MR-1004; its proposal was made before the change. As carol, import C, which removes the serialNumber field, then build, test and try to activate it.

    You should see: the gateway keeps its identity; the old approval is rejected with 409 stale_dependency; C is blocked and refused activation; the dashboard keeps serving A and reports it is 2 versions behind.

  5. Fix it without changing the API carol

    Approve projection 1.1.0, which maps serialNumber to the renamed source field, then build and run the consumer checks.

    You should see: the contract diff is empty (consumers see the same API) and the candidate is tested_pass.

  6. Survive a lost acknowledgment carol

    Pause the outbox, click Inject lost-ack fault, activate, then click Deliver now twice and resume the outbox. Then click Retry last request with same key.

    You should see: the first delivery reports no acknowledgment and the second is acknowledged. The dashboard shows 2 deliveries but 1 effect. The retry returns the original result (Idempotent-Replay: true).

The full spoken script, with timings and fallbacks, is in workbench/DEMO_SCRIPT.md. A recorded run is in examples/demo_transcript.txt; present it as a recording.

How to use it · 4

Put it online with Railway

About five minutes in the Railway dashboard. The full steps are in workbench/DEPLOY.md.

  • New project from GitHub: cal2020/hello-world-app, branch claude/kbr-interview-prep-s59ic7.
  • Settings: Root Directory workbench, config file /workbench/railway.json.
  • Variable LWB_ACCESS_CODE: a random value of at least 16 characters. Don't set PORT.
  • Add a volume at /data, keep replicas at 1, and generate a domain.
  • Open the URL, enter the code, and you get the same UI. The consumer dashboard is at /consumer/.

Generate a code with:

python3 -c "import secrets; print(secrets.token_urlsafe(18))"

To reset the hosted demo between sessions, set LWB_RESET_ON_START=1, restart, then remove the variable.
