# hexis-service in the browser

A JavaScript port of the `hexis_service` engine that runs entirely client-side, plus an interactive lab UI.
It is bundled into **one self-contained HTML file** (`dist/hexis-lab.html`) suitable for publishing as an
Artifact: no server, no network calls, no external scripts. The Python package in `../src/hexis_service`
is the **reference implementation**. The JS port must reproduce its behavior, and that is proven by
differential tests against "golden" outputs generated by running the real Python code.

## Layout

```
browser/
  src/NN_<module>.js      engine modules (plain ES2020 scripts, loaded in filename order)
  app/                    UI: index.template.html, NN_*.css, NN_*.js (loaded after the engine)
  golden/gen_<module>.py  generators that run the Python reference and write golden/<name>.json
  golden/*.json           committed golden vectors (regenerate with: python golden/gen_all.py)
  test/NN_<module>.test.js  Node tests (engine), run by test/run.mjs
  test/e2e/               Playwright browser tests of the bundled page
  build.py                bundles src + app + embedded data into dist/
  dist/                   build output (hexis-lab.html = Artifact fragment; hexis-lab.local.html = full page + CSP for local tests)
```

## Module conventions (mandatory)

* Every `src/*.js` file is a classic script (no `import`/`export`, no `require`) wrapped in an IIFE that
  registers one namespace on the global `HX`:
  ```js
  (function (HX) {
    "use strict";
    const guards = (HX.guards = HX.guards || {});
    // ... definitions ...
  })(globalThis.HX = globalThis.HX || {});
  ```
* A module may reference other namespaces **only inside function bodies**, never at load time. The one
  exception is subclassing the error bases defined in `00_hx.js` (`HX.HXError`), which always loads first.
* **The API mirrors the Python API:** same snake_case function and method names, same argument order,
  keyword arguments become a trailing options object (`validate_package(pkg, catalog, profile, {skill_text,
  deployment_policy})`). Python classes become JS classes with the same name. Pydantic models become plain
  JSON objects with **exactly** the fields of `model_dump(mode="json", by_alias=True)` (all defaults
  present), so canonical digests match Python byte for byte.
* Exceptions: Python exception classes become JS classes extending `HX.HXError` with the same name and the
  same `code`/`message`/`detail` fields (e.g. `HX.kernel.KernelError`, `HX.service.RunError`).
* Synchronous engine. No `async`, no Promises, no timers in `src/`. Time comes from an injected `clock()`
  (seconds, like Python), ids from an injected id generator. Never call `Date.now()`/`Math.random()` in
  engine code except as an overridable default.
* No network, DOM or storage access in `src/`. (The UI in `app/` may use the DOM.)
* Numbers: JS has one number type. Integers are canonicalized as integers and non-integers with Python's
  float `repr` rules (`HX.canonical`). Integral floats such as `1.0` cannot be represented and are rejected
  by the strict parser. Engine data must not rely on them.

## Tests

* `node test/run.mjs [filter...]` loads every `src/*.js` in order into one context, then every
  `test/*.test.js`, and runs the registered tests. Test files use the globals `test(name, fn)`,
  `skip(name, reason)`, `assert` (Node's `assert/strict`) and `golden(name)` (parsed `golden/<name>.json`).
* Each module owner writes `golden/gen_<module>.py` (using `golden/_common.py`), commits the generated
  `golden/<module>*.json`, and writes `test/NN_<module>.test.js` that asserts parity with it.
* Parity means: identical values, digests, finding codes, statuses, paths and counts. Error *messages* need
  not match word for word; error *codes/categories* must. Any deliberate deviation from Python must be
  conservative (never more permissive), documented in `DEVIATIONS.md`, and covered by a test.

## Build

`python build.py` writes:
* `dist/hexis-lab.html`: the Artifact fragment (no doctype/html/head/body; starts with `<title>`).
* `dist/hexis-lab.local.html`: the same page wrapped in a full document with a strict CSP meta (no network)
  for local Playwright testing.

Each engine module and each app script becomes its own `<script data-hx-module="src/NN_x.js">` element. A
module that fails to parse or throws while loading only loses its own namespace; the UI reports missing
namespaces instead of failing as a whole. `python build.py --engine-prefixes 00,05,10,15` includes only the
listed engine modules, for UI work against a partially ported engine.

The build fails if the output references any external URL other than Google Fonts.

`node test/e2e/run.mjs [filter...]` runs the Playwright tests in `test/e2e/` against
`dist/hexis-lab.local.html` at 1280px and 400px in light and dark color schemes.
